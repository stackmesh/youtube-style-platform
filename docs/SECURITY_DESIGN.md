# Security Design

**Status: identity, catalogue ACL, private uploads, HLS packaging, and playback authorization are implemented. Comments, reactions, subscriptions, and moderation routes are not.**

Stage 04 does not put `S3_ADMIN_ACCESS_KEY` or `S3_ADMIN_SECRET_KEY` in the API. Presigned part URLs are the only storage capability the browser receives. They expire after `UPLOAD_PART_URL_TTL_SECONDS` (20 minutes by default), bind `Content-Length`, and cannot choose the object key. Anonymous `GET` of an original remains denied. Upload and processing errors returned to the client use stable codes and do not include FFmpeg command lines.

This document defines how the platform authenticates users, authorizes actions, and resists the abuses that a video site attracts. It does not claim these controls have been built or tested.

Canonical decisions: ADR-003, ADR-004, ADR-005, ADR-011, ADR-012, ADR-013, ADR-022, ADR-023, ADR-025, ADR-031, ADR-032.

## 1. Trust boundaries

| Zone | Trust |
| --- | --- |
| Browser | Untrusted. UI checks are not security checks |
| Caddy on the public internet | Terminates TLS. Does not make authorization decisions |
| FastAPI | Trusted to enforce identity, ACL, quota, and roles |
| Worker | Trusted with object-storage credentials and FFmpeg. Not reachable from the network |
| PostgreSQL, Redis, SeaweedFS | Private Docker network only. No published ports |
| S3 application credentials | API and worker environment only. Never in the frontend bundle, never in presigned URLs as raw keys, never in logs |
| storage admin credentials | SeaweedFS server process and the one-shot init container only. The API refuses to start if it sees them |

Presigned URLs are capabilities. They are created only after the API has authorized the action, they are scoped to one object and one method, and they expire quickly.

## 2. Authentication

### 2.1 Passwords

- Hashed with Argon2id via `argon2-cffi`.
- Parameters, chosen for a small server: memory 64 MiB, time cost 3, parallelism 1. If login latency on the target host is above 500 ms, lower memory to 32 MiB rather than switching algorithms. Record the change in configuration, not in code comments only.
- The hash string is stored in `users.password_hash`. The plaintext password is never stored, logged, or put in an error response.
- Password rules: 10 to 128 characters, no maximum below 128, no required character classes. The UI may show a strength hint. The server rejects only length.
- Registration and login use a dummy Argon2 verify against a precomputed hash when the email does not exist, so the response time does not reveal whether the email is registered. The HTTP result is still a generic `401 INVALID_CREDENTIALS` for a bad login. Registration of an existing email returns `409 EMAIL_TAKEN` because the user needs to know why signup failed. That endpoint is rate limited.

### 2.2 Tokens

| Credential | Lifetime | Storage | Presentation |
| --- | --- | --- | --- |
| Access JWT | 15 minutes | Browser memory only | `Authorization: Bearer` |
| Refresh token | 14 days | SHA-256 hash in `refresh_tokens`. Raw value only in an `HttpOnly` cookie named `refresh_token` | Cookie `Path=/api/v1/auth`, `SameSite=Lax`, `Secure` when `COOKIE_SECURE=true`. Not stored in `localStorage` or `sessionStorage` |
| Playback session | 6 hours | Row id in `playback_sessions`, UUID v4 | Cookie `hls_session`, `HttpOnly`, `Path=/api/v1/videos/{video_id}`, `SameSite=Lax` |

JWT:

- Algorithm HS256 only. `none` and any RSA algorithm are rejected even if the header says otherwise.
- Secret is at least 32 bytes, from `JWT_SECRET`, generated by the setup script.
- Claims: `sub` (user id), `iat`, `exp`, `jti`, `epoch`. No role claim. Role and `is_active` are loaded from PostgreSQL on every authenticated request so a demotion or ban applies immediately (ADR-005).
- `epoch` must equal `users.session_epoch`. Logout, ban, and deactivation increment `session_epoch`, which rejects access tokens issued before that event.
- Clock skew allowance: 30 seconds.

Refresh:

- 256 bits of randomness, base64url encoded.
- On refresh, the old row is revoked and a new row is inserted in the same family, in one transaction. The cookie is replaced.
- The browser shares one in-flight refresh call. A second caller waits for that result instead of presenting the same token again. Two completed uses of one refresh token still revoke the family.
- Presenting a refresh token whose row is already revoked revokes every token in that `family_id` and clears the cookie. This cuts off a stolen token after rotation.
- Logout revokes the presented refresh token's family, sets `revoked_at` on that user's active playback sessions, and increments `users.session_epoch` in that same transaction.
- The access token is not stored in a denylist. Immediate logout works because the next request compares the token's `epoch` with `users.session_epoch` and rejects a mismatch.

`session_epoch` is an integer column on `users`, not null, default 1.

Ban and deactivation do the same epoch increment, revoke refresh families, revoke playback sessions, and set `is_active = false`. Reactivation does not restore old tokens. The user logs in again.

### 2.3 Cookie and CSRF posture

State-changing routes require a bearer access token. They do not authenticate from the refresh cookie. A cross-site form post cannot attach the bearer token.

The refresh route is cookie-authenticated and is safe against cross-site use because:

- `SameSite=Lax` cookies are not sent on cross-site `POST`
- the route is `POST` only
- the cookie path is `/api/v1/auth`

Playback cookies are sent on same-site `GET` requests for playlists and segments. Those routes are read-only. `SameSite=Lax` is correct. `SameSite=None` is not used.

The access token must not be placed in `localStorage` or `sessionStorage`. CORS stays `allow_credentials=false`. The browser sends the refresh cookie on same-origin `/api/v1/auth` requests. Mutations other than refresh still require the bearer token.

The process refuses to start when `PUBLIC_APP_URL` uses `https` and `COOKIE_SECURE` is false. Local HTTP keeps `COOKIE_SECURE` false.

### 2.4 Registration

Creates `users`, `channels`, and `user_storage_quotas` in one transaction. Role is always `USER`. A client-supplied role is ignored.

The first `ADMIN` is created only by the bootstrap path when no admin exists. Bootstrap refuses to run if an admin already exists. `BOOTSTRAP_ADMIN_PASSWORD` is required. The historical placeholder `unused-until-stage-2` is rejected and is never stored. The bootstrap password is not written to logs.

## 3. Authorization

### 3.1 Role matrix

| Action | USER | MODERATOR | ADMIN |
| --- | --- | --- | --- |
| Manage own channel, videos, playlists, grants | yes | yes | yes |
| Comment, react, subscribe, report others' videos | yes | yes | yes |
| List and resolve reports | no | yes | yes |
| Hide and restore videos | no | yes | yes |
| Open a private video in the moderation player | no | only if hidden or at least one report exists | same as moderator |
| Change roles, deactivate, reactivate | no | no | yes |

Every moderation and admin action requires a non-empty reason and writes `moderation_actions`. The audit trigger rejects updates and deletes (ADR-012).

A role change does not increment `session_epoch` and does not revoke refresh tokens. The new role is read from PostgreSQL on the next request. Deactivation and ban do increment the epoch, because those must stop the session rather than only change a permission.

A moderator cannot change their own role. An admin cannot demote or deactivate the last active admin. An admin cannot change their own role in a way that removes the last admin. The check counts active admins inside the same transaction as the update.

### 3.2 Video ACL

Evaluated by `viewer_can_see` in `app/catalogue/acl.py`, not in the router and not in the frontend. `require_visible_video` is the read path later stages call. Stage 3 uses it for detail, related videos, and every discovery query uses the same public predicate.

A caller can **know that a video exists** when any of these is true:

- they own it
- visibility is `public` or `unlisted` and moderation is `visible` and the video is `ready` and not deleted
- visibility is `private`, an active grant exists, moderation is `visible`, the video is `ready`, and it is not deleted
- they are moderator or admin, the route is under `/moderation`, and the video is hidden or has a report

Otherwise the service raises `NotFound`. The HTTP status is 404 with `VIDEO_NOT_FOUND`. The API does not return 403 for "this private video exists" (ADR-011).

Playback requires the same ACL plus `processing_status = ready`.

Comments, reactions, and view counts use the same ACL. A user who cannot see a video cannot read or write its comments.

Owner metadata endpoints return the video even when it is `draft`, `uploading`, `failed`, `hidden`, or `abandoned`, so the studio page can show status. Those responses are still 404 for everyone else.

### 3.3 Grants

- Only the owner can create or revoke a grant.
- The grantee is identified by handle. The API does not accept raw user ids from the client for this operation, which avoids using the grant form as an id oracle. The response returns the handle, not the email.
- Creating a grant for a missing handle returns 404 `CHANNEL_NOT_FOUND`.
- Self-grant and grant to the owner are `409`.
- Duplicate active grant is `409`.
- Grants do nothing while the video is public or unlisted, and start applying again if it returns to private (ADR-013).
- Revocation increments `acl_version` and does not delete the row.

### 3.4 Private playback

See [VIDEO_PIPELINE.md](VIDEO_PIPELINE.md) section 6. Security properties:

- The bucket has no public read policy.
- The playback cookie is path-scoped to one video. A cookie for video A is not sent to video B's HLS routes.
- The session row stores the video id, and the route checks it matches, so a stolen cookie cannot be moved to another path by the attacker. The browser would not send it to another path anyway; the check covers a buggy client.
- Segment routes re-check ACL and then redirect with a two-minute presign.
- Presigns are `GET` only, for the exact object key of that segment, not for a prefix.
- Moderator access to a private or hidden video writes `view_private_video` before the session is created.

### 3.5 Object and database consistency

Authorization state lives in PostgreSQL. Object storage does not have a parallel ACL. Anyone with a valid presign can fetch that object until it expires. The API therefore mints presigns only at the last moment and only for two minutes.

Upload presigns are `PUT` for one part of one upload id. They expire in 20 minutes. A presign for video A's upload cannot write video B's key because the key and upload id are bound into the signature.

If the database says a video is deleted and SeaweedFS still has bytes, the bytes are unreachable because no route will presign them and the bucket is private. The sweeper removes them.

## 4. Upload and file validation

Validation is layered. Any single layer can be bypassed by a crafted client, so all of them run.

| Layer | When | What |
| --- | --- | --- |
| Authentication | Initiate | Anonymous clients cannot initiate an upload |
| Metadata | Create and initiate | Length limits, tag grammar, visibility enum |
| Declared type | Initiate | Allow-list of video content types |
| Size | Initiate | `1 .. MAX_UPLOAD_BYTES` |
| Quota reservation | Initiate | Row lock, reserve `expected_size` before SeaweedFS accepts parts |
| Concurrency | Initiate | Cap active sessions per user |
| Rate limit | Initiate | 10 per hour per user, 30 per hour per IP |
| Part scope | Presign | Only part numbers that belong to this session, batch size ≤ 20 |
| Part numbers | Presign and complete | Integers, unique, only `1 .. part_count`, batch ≤ 20, and `part_count` ≤ 512 |
| Part length | Presign | SigV4 signs `Content-Length`. Non-final parts are exactly 16 MiB. The final part is the exact remainder. SeaweedFS rejects any other length |
| Stored parts | Complete | `ListParts` must be exactly those part numbers and sizes. Client ETags must match. Sum must equal `expected_size` with no tolerance |
| Object size | Complete | `HEAD` `Content-Length` must equal `expected_size` |
| Duplicate and concurrent complete | Complete | A finished session returns the current video. A second in-flight caller receives `409 UPLOAD_IN_PROGRESS` |
| Expiry and abandon | Sweeper and lifecycle | API refuses expired sessions. Sweeper aborts them. SeaweedFS lifecycle aborts incomplete multipart uploads after 1 day |
| Media probe | Worker | Real container, at least one video stream, duration and dimension caps |
| FFmpeg sandbox | Worker | Non-root user, `-protocol_whitelist file,pipe`, `-nostdin`, process-group timeout, no network needed |
| Thumbnail and avatar | API | Size cap, decode with Pillow, dimension cap, re-encode to JPEG, metadata stripped |

The client filename is not used as a storage key.

A polyglot file that is a valid video and also contains another payload is stored as the original and transcoded into HLS. The HLS output is what viewers play. The original is never served to viewers. Operators should still treat originals as untrusted input. The worker container has no published port and no broader role than reading and writing the media bucket.

Image uploads are re-encoded so the stored thumbnail is not the original file. This removes EXIF and most content smuggled past a MIME check (ADR-023).

Quota and reservation details are in [VIDEO_PIPELINE.md](VIDEO_PIPELINE.md) and ADR-025. The split between API checks and SeaweedFS checks is in that document, section 3.7. The rule that matters here: a presigned part URL cannot store more bytes than the length in its signature, and that length was reserved against the user quota before the URL existed.

## 5. Object storage

SeaweedFS is private infrastructure. Its S3 gateway is the only storage API the application uses. The browser talks to the public S3 hostname only with URLs the API has just signed. Administrative credentials never reach the browser, the OpenAPI examples, or the API process.

### 5.1 Network

| Path | Exposure |
| --- | --- |
| `seaweedfs:8333` | S3 gateway on the Docker network. Compose does not publish it |
| Master `9333`, volume `8080`, filer `8888` | Bound to loopback inside the SeaweedFS container. Filer HTTP is disabled. No admin UI is published |
| `https://s3.<domain>` | Caddy site that reverse-proxies to `seaweedfs:8333` and preserves `Host` |
| API and worker | Use `S3_ENDPOINT_URL=http://seaweedfs:8333` for `ListParts`, `HEAD`, complete, abort, and server-side reads. They do not use the public URL for those calls |

Startup of the API process checks three things and exits if any fail: the bucket exists, an anonymous `GetObject` of a probe object is rejected, and `S3_ADMIN_ACCESS_KEY` / `S3_ADMIN_SECRET_KEY` are absent from the API environment. Readiness uses the application credentials to confirm the bucket is reachable. It does not use the storage-admin identity.

### 5.2 Identities and bucket policy

SeaweedFS authorizes S3 calls from an identity file loaded only by the storage process. Anonymous has no actions. `media-app` is limited to bucket `media`: `Read`, `Write`, `List`, `Tagging`, `ListBucketMultipartUploads`, and `ListMultipartUploadParts`. The storage-admin identity can create the bucket, set CORS, set the lifecycle rule, and set the bucket quota. `media-app` cannot.

Init does not install a bucket policy whose principal is `*`. If a bucket policy is present and an `Allow` statement uses principal `*` or action `s3:*`, API startup fails. Anonymous access is rejected even when no bucket policy document is stored, because the anonymous identity has an empty action list.

A hard bucket quota, `S3_BUCKET_QUOTA_BYTES`, is set by init with the SeaweedFS `?seaweedfs-quota` subresource. It limits total disk use if an application bug signs a bad URL. It does not replace per-user reservations. The application identity cannot read or change that quota.

Lifecycle: abort incomplete multipart uploads after 1 day. Objects are not expired by lifecycle. Deletion of a video's prefixes is the sweeper's job.

### 5.3 CORS

CORS is set on the bucket and answered by the S3 gateway. One origin. Credentials are off. The browser does not send cookies to `s3.<domain>`. The gateway `-s3.allowedOrigins` value is the same origin, so it does not add `*`.

| Field | Value |
| --- | --- |
| Allowed origin | `PUBLIC_APP_URL` only. No `*` |
| Allowed methods | `GET`, `PUT`, `HEAD` |
| Allowed headers | `Content-Type`, `Content-Length`, `x-amz-*` |
| Expose headers | `ETag` |
| Max age | 300 seconds |

`ETag` is exposed so the browser can read the part ETag after `PUT` and send it to complete. The API still treats `ListParts` as the authority and only uses the client ETag as a match check. No other response header is exposed. `DELETE`, `POST`, and `*` methods are not allowed. A second origin is not added for convenience.

### 5.4 Presigned URL lifetime

| URL | Method | Lifetime | Bound to |
| --- | --- | --- | --- |
| Upload part | `PUT` | 20 minutes | Key, upload id, part number, `Content-Length` |
| Segment after an authorized segment request | `GET` | `PLAYBACK_SEGMENT_TTL_SECONDS` (120) | One object key |
| Thumbnail embedded in JSON | `GET` | 120 seconds | One thumbnail key |

All three use SigV4 and `S3_PUBLIC_ENDPOINT_URL`. None of them are prefix wildcards. Upload URLs are not valid as `GET`. Segment URLs are not valid as `PUT`.

### 5.5 Hostname

TLS mode requires all of these to agree, and `ubuntu-up.sh` refuses to start if they do not:

- `PUBLIC_DOMAIN=example.com`
- `PUBLIC_APP_URL=https://example.com`
- `S3_PUBLIC_ENDPOINT_URL=https://s3.example.com`
- `CORS_ORIGINS=https://example.com`
- Caddy site label `s3.example.com`

Addressing is path-style: `https://s3.example.com/media/originals/{video_id}/source`. The presigner and Caddy must use that host so the signature matches the `Host` header the S3 gateway sees. Demo HTTP mode uses `http://s3.localhost` only on a loopback deploy and prints that it is not a production configuration.

### 5.6 Credentials

| Secret | Who receives it |
| --- | --- |
| `S3_ADMIN_ACCESS_KEY`, `S3_ADMIN_SECRET_KEY` | SeaweedFS server and `s3-init` only. Stored in `/opt/youtube-clone/.env.seaweed-admin`, mode 600 |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | `media-app` identity. API and worker only. Also present in the SeaweedFS identity file so the gateway can verify signatures. Stored in `.env`, mode 600 |

Init is safe to run again and does not rotate `media-app`. The API, worker, edge, and frontend services do not use `env_file` for the admin file. If admin variables are present in the API process, the process exits before it listens.

Rotation is an operator procedure: create a new access key, restart API and worker, then disable the old key. The first release does not rotate automatically.

### 5.7 When object storage is unavailable

| Operation | Behavior |
| --- | --- |
| Initiate, after the reservation is committed, if `CreateMultipartUpload` fails | Release the reservation, mark the session `aborted`, return the video to `draft`, `503 STORAGE_UNAVAILABLE` |
| Presign | Does not call SeaweedFS. If the last readiness snapshot says SeaweedFS is down, still return `503` so the client does not receive URLs that cannot be stored. The snapshot is the ready check's SeaweedFS result, refreshed at least every 10 seconds |
| Complete, network error before `CompleteMultipartUpload` | `503 STORAGE_UNAVAILABLE`. Session returns to `initiated`. No job is inserted |
| Complete, network error after `CompleteMultipartUpload` was attempted | `HEAD` decides. A verified object is finalized. A missing object returns the session to `initiated`. If `HEAD` fails too, the session stays `completing` and a retry receives `409` until the lock window passes |
| Complete, verification rejection | Abort as in the pipeline document. This is a client error, not an outage |
| Playlist read | `503 STORAGE_UNAVAILABLE` |
| Segment redirect | The ACL check does not need SeaweedFS. Signing a URL does not either. If SeaweedFS was down at the last probe, return `503` instead of a URL that will fail in the player |
| Worker download or artifact upload | Retryable `storage_error` |
| Readiness | `503` with `checks.s3=fail` |

The API does not fall back to a public URL or skip the ACL when SeaweedFS is down.

## 6. Rate limiting

Algorithm: sliding window in Redis, key prefix `rl:`. If Redis is unavailable, the API returns `503 SERVICE_UNAVAILABLE` for routes that require a limit. It does not fail open (ADR-022).

| Route group | Limit |
| --- | --- |
| `POST /auth/register` | 5 per hour per IP |
| `POST /auth/login` | 10 per 15 minutes per IP, and 10 per 15 minutes per email |
| `POST /auth/refresh` | 60 per hour per user |
| `POST /videos` and upload initiate | 10 per hour per user and 30 per hour per IP |
| Upload part presign | 120 per hour per user |
| Comments | 20 per 10 minutes per user |
| Reports | 10 per hour per user |
| Reactions and subscriptions | 60 per 10 minutes per user |
| Search | 60 per minute per IP |
| Playback session create | 30 per 10 minutes per user or per IP |
| Playlist and segment HLS routes | 600 per minute per playback session |

Limits are per process-shared Redis keys, so two Uvicorn workers do not double the allowance.

The HLS limit is high enough for a seek that pulls a burst of segments and for one ABR switch. It is low enough that one session cannot use the segment route as an open proxy hammer. A 6 second segment cadence is about 10 requests per minute.

Responses use `429` and `Retry-After`. The error code is `RATE_LIMITED`.

## 7. Web vulnerabilities

| Risk | Control |
| --- | --- |
| SQL injection | SQLAlchemy bound parameters. No string-built SQL. Dynamic sort columns are an allow-list in code |
| XSS | React default escaping. Comments and descriptions are plain text. `Content-Type: application/json` on API responses. CSP on the frontend: default-src `'self'`; media and connect allowed to `self` and `s3.<domain>`; no inline scripts. The Vite build uses hashed assets without inline handlers |
| CSRF | Bearer token for mutations. `SameSite=Lax` cookies. No cookie-authenticated mutations except refresh, which is Lax-protected |
| Clickjacking | `Content-Security-Policy: frame-ancestors 'none'` and `X-Frame-Options: DENY` |
| MIME sniffing | `X-Content-Type-Options: nosniff`. Thumbnails served as `image/jpeg` from SeaweedFS after re-encode |
| Open redirect | The segment endpoint redirects only to a URL this process just presigned on `S3_PUBLIC_ENDPOINT_URL`. The `Location` host is checked against that configured host before the response is sent |
| SSRF | The server does not fetch user-supplied URLs. FFmpeg cannot open network protocols |
| IDOR | Every object load goes through the ACL or an owner check. UUID v7 identifiers are not authorization |
| Mass assignment | Pydantic request models list fields explicitly. `role`, `subscriber_count`, `view_count`, and processing fields are not accepted from clients |
| Privilege escalation | Role is server-assigned. Moderation dependencies load the user from the database and require the enum |
| User enumeration | Login responses are generic. Registration conflict on email is accepted and rate limited. Grant lookup is by handle and is also rate limited with the general authenticated limit of 120 requests per minute per user |
| Brute force | Login rate limits plus Argon2 cost |
| Token theft via XSS | Access token is in memory. Refresh and playback cookies are `HttpOnly`. CSP reduces XSS impact. A successful XSS can still call the API as the user while the page is open; CSP and escaping are the preventive controls |
| Replay of presigned upload | URLs expire in 20 minutes and are bound to the upload id, part number, and `Content-Length`. Complete compares `ListParts` with the declared size |
| Path traversal | Object keys are built from UUIDs and a fixed suffix. User filenames and tag strings are never interpolated into keys |
| Dependency and image risk | Images pinned by major version in Compose. The implementation stage pins digests or patch versions before the deployment stage is called done. Containers run as non-root |
| Information leaks | 500 responses have no stack trace. Presigned URLs are not logged. 404 is used for hidden private existence |
| Unrestricted file upload | Caps, allow-lists, quota, probe, and re-encode as above |
| Denial of service | Upload caps, one transcode by default, FFmpeg timeout, request body limit of 2 MB on the API (thumbnails and avatars), JSON body limit 256 KB, rate limits |
| CORS | Application API allows only `CORS_ORIGINS`, the methods the API uses, and the `Authorization` header. Credentials are off on that CORS policy because mutations use a bearer token. Same-origin refresh and HLS routes do not need CORS. The S3 host uses the bucket CORS in section 5.3 |
| TLS | Caddy obtains certificates when a public domain is set. Cookies are `Secure` in that mode. Demo HTTP mode is labeled insecure in the setup script output |
| Security headers | `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` disabling camera and microphone, HSTS when TLS is on |
| Secret handling | `.env` mode 600, not committed. `.env.example` contains keys and empty values only |
| Audit | Privileged actions and moderator views of private or hidden videos are append-only |

Authenticated request rate of 120 per minute per user is a backstop on top of the tighter limits above.

## 8. Privacy notes

- Emails are not shown on channel pages or in search.
- IP addresses are not stored in the clear. Anonymous view dedupe stores a daily-salted SHA-256 of IP and user agent, and the row is deleted after 48 hours. The salt is in process memory and in a Redis key with a 48 hour TTL, not in PostgreSQL. Losing the salt early only under-counts views.
- This dedupe approach is a deliberate tradeoff. It is not a full anonymity design. It is listed as an assumption so it can be removed if the product owner rejects IP-derived hashes.
- Logs may contain user ids and video ids. They must not contain passwords, tokens, or presigned query strings.
- Account deletion is not in the first release. Deactivation stops login and playback-session creation. Videos remain until an operator handles them. This is a known gap, not a silent omission.

## 9. Security tests the implementation must include

These tests do not exist yet. Each row names the stage that must automate it. Stage 11 runs the whole list and fails if a row has no test. Authorization is asserted at the metadata route and, once playback exists, at the playlist and segment routes. A passing metadata test does not stand in for a segment test.

### 9.1 Private video access

Fixture: a `ready` private video with HLS objects, owner O, approved grantee G, stranger S (authenticated, no grant), anonymous client A, moderator M. A second private video, N, has never been reported and is not hidden.

| Test | Expected | Stage |
| --- | --- | --- |

| S, same five calls | 404 on every one | 3 and 6 |

### 9.3 Upload and bucket limits

| Test | Expected | Stage |
| --- | --- | --- |
| Part numbers `0`, `-1`, `part_count + 1`, a duplicate, and a batch of 21 | 422 `UPLOAD_PART_INVALID`. No URL in the body | 4 |

### 9.4 Other controls

- An unlisted video is watchable with the id and absent from feed, search, related videos, and the public channel list. Stage 3.
- A client-supplied `role` on registration does not create a moderator. Stage 2.
- Logout increments epoch: the old access token is rejected, and the old refresh token is rejected. Stage 2.
- Reuse of a rotated refresh token revokes the family. Stage 2.
- A non-video payload that passes the content-type allow-list is marked `failed` with `invalid_media` and never becomes `ready`. Stage 5.
- The moderation audit trigger rejects `UPDATE` and `DELETE`. Stage 10.
- Segment redirect `Location` host equals `S3_PUBLIC_ENDPOINT_URL`. A unit test of the host check rejects any other host. Stage 6.

## 10. Residual risk

- A stolen access token works until logout's epoch check. Epoch check closes that on logout. A stolen token before logout works until logout or expiry. That is normal for bearer tokens.
- iOS fallback playlists, if enabled, lengthen the revoke window to the presign TTL of those URLs.
- FFmpeg and Pillow can have memory-corruption bugs. Isolation is non-root, no published port, protocol whitelist, and timeouts. It is not a sandbox such as gVisor. That extra sandbox is out of scope on a single Docker host unless the operator adds it later.
- One server is a single point of compromise. Disk encryption and host hardening are operator responsibilities. The application design does not replace them.
- There is no email verification, so disposable accounts can upload until quotas and rate limits stop them.
- The SeaweedFS process holds the storage-admin identity because the S3 gateway has to load it. Those values are not in the API, worker, edge, or frontend environment. A person who can read that container environment can administer the bucket.
- If a future change signs part URLs without `Content-Length`, a client can store parts larger than the reservation until the sweeper aborts them. The stage 4 oversized-`PUT` test is what keeps that regression visible. The bucket quota limits the damage and does not make the bug acceptable.
